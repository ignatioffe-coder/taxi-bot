# 🚕 MOVENTA

Telegram Mini App для водителей такси и курьеров: показывает спрос по районам
Москвы, помогает записывать смены и считать чистый доход после расходов.

## Возможности

- 🚕 Отдельная статистика для такси и курьерских смен
- 👥 Два независимых направления в одном аккаунте: такси и доставка
- ⏱️ Прогноз на 30, 60 и 120 минут: переключатель горизонта прямо в карточке районов
- 🌤️ Погода в шапке и почасовой прогноз на ближайшие часы от Open-Meteo
- 💰 Выручка, чаевые, комиссии, топливо/зарядка, аренда, обслуживание, налоги, связь и амортизация
- 📊 Чистый и экономический доход, средний чек, длительность заказа, расходы на километр и динамика по периодам
- 🎯 Прогресс недельной цели по чистому доходу
- 🧭 Все 132 района в 12 административных округах, включая Новую Москву
- 🗺️ Карта Яндекс.Карт с границами районов и слоями коэффициентов/прогноза; коэффициенты актуальны 2 часа, история сохраняется
- 🗣️ Короткие сообщения водителей и курьеров с ограничением частоты, анонимной публичной лентой, подтверждением несколькими авторами и модерацией
- 📍 Прозрачная оценка перспективных районов: коэффициенты, история похожего
  времени, погода, плотность заведений, сообщения водителей о пробках и спросе,
  дорожные инциденты TomTom, а также события и аэропорты, если подключены источники
- 🧾 Подсказки: приложение объясняет, почему смена не попала в прогноз (нет
  района, нет часов или смена записана в другом направлении)
- 🔍 Блок «Как считается прогноз»: какие факторы участвуют сейчас и что балл —
  это сравнение районов, а не число заказов
- 📉 Сохранение прогнозов и последующее сравнение с коэффициентами или личными сменами
- 🛠️ Для администраторов: сводные метрики, покрытие районов данными и пять
  районов с наибольшей ошибкой прогноза
- 🔔 Уведомления о спросе, погоде и дорожной обстановке с настройками и «тихими часами»
- 🌤️ Текущая погода Москвы с явной отметкой недоступности источника
- 🛡️ Выгрузка и удаление данных пользователя; для администраторов — сводные метрики и модерация сообщений
- 🆓 7 дней пробного доступа, затем подписка ЮKassa за 500 ₽ на 30 дней
- 💳 Оплата в Mini App через защищённую страницу ЮKassa; автопродление можно отключить в профиле
- 📱 В самом Telegram-боте доступна только кнопка запуска Mini App
- 🧑 При первом открытии Mini App пользователь указывает имя и выбирает такси или курьерскую работу; профиль сохраняется один раз

### Подписка и ЮKassa

После заполнения профиля начинается бесплатный пробный период на 7 дней. Он
предоставляется один раз на аккаунт Telegram; у пользователей с уже созданным
профилем он начинается при первом запуске приложения после включения подписок.
Подписка стоит 500 ₽ за 30 дней. При подтверждении первого платежа способ оплаты
сохраняется в ЮKassa для автоматического списания раз в 30 дней. Подтверждение
платежа обрабатывается webhook’ом, а приложение сверяет его с данными API
ЮKassa. Автопродление можно отключить в профиле MOVENTA; доступ остаётся до конца
оплаченного периода. Текущий статус, дата окончания и состояние автопродления
показываются в профиле.

Для работы оплаты задай `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` в окружении.
В кабинете ЮKassa настрой webhook на публичный endpoint
`/api/yookassa/webhook` для событий `payment.succeeded` и `payment.canceled`.
Автоплатежи должны быть отдельно разрешены для магазина ЮKassa; без одобрения
поддержки провайдера не включай автопродление в реальном магазине. Проверь также
настройку чеков и соответствие требованиям 54-ФЗ. Команда `/terms` показывает
условия, а `/paysupport` позволяет отправить вопрос
по оплате администратору бота. Ответить пользователю администратор может
командой `/reply <user_id> <текст>`. Для доставки обращений администратор должен
сначала открыть чат с ботом и отправить `/start`.

## Быстрый старт

1. Клонируй репозиторий:
   ```bash
   git clone https://github.com/ignatioffe-coder/taxi-bot.git
   cd taxi-bot
   ```

2. Создай виртуальное окружение и установи зависимости:
   ```bash
   python -m venv venv
   source venv/bin/activate   # Linux/macOS
   # или venv\Scripts\activate  # Windows
   pip install -r requirements.txt
   ```

3. Создай файл `.env`:
   ```env
   BOT_TOKEN=твой_токен_от_BotFather
   WEBAPP_URL=https://bot-1792186571-5969-taxi-bot.bothost.tech
   YANDEX_MAPS_API_KEY=ключ_JavaScript_API_Яндекс.Карт
   ```
   Mini App требует публичный HTTPS-домен. Для указанного BotHost адрес уже
   задан в конфигурации по умолчанию. Бот запускает веб-сервер на порту из
   переменной `PORT` (по умолчанию `8080`); для другого домена переопредели
   `WEBAPP_URL`.    Telegram-данные Mini App проверяются на сервере подписью токена
   бота. Доходы и расходы хранятся отдельно для каждого направления и
   агрегируются за день, неделю или месяц.
   Чтобы отображалась карта, создай ключ JavaScript API в
   [кабинете разработчика Яндекса](https://developer.tech.yandex.ru/) и
   укажи для ключа разрешённый домен Mini App. Ключ передаётся браузеру,
   поэтому обязательно ограничь его доменом приложения.

4. Запусти бота:
   ```bash
   python bot.py
   ```

## Структура проекта

- `bot.py` — запуск приложения из Telegram
- `mini_app.py`, `static/` — интерфейс Mini App, API и Telegram-аутентификация
- `static/district-boundaries.json` — упрощённые границы районов из OpenStreetMap (ODbL 1.0)
- `districts.py` — административные районы, сгруппированные по округам
- `config.py` — конфигурация
- `database.py` — работа с SQLite
- `subscriptions.py` — тариф ЮKassa, пробный период и условия подписки
- `yookassa.py` — создание и проверка платежей ЮKassa
- `analytics.py` — рекомендации и статистика
- `demand_forecasting.py` — оценки спроса по доступным данным с указанием уверенности и ограничений
- `crowd_signals.py` — сообщения водителей и курьеров как множитель к баллу
- `external_factors.py` — погода (Open-Meteo), плотность заведений и подключение внешних факторов
- `tomtom_traffic.py` — текущие инциденты TomTom и оценка влияния на дорожную доступность районов
- `airports.py` — влияние прилётов рядом с аэропортами (источник подключается через `FLIGHTS_API_URL`)
- `events.py` — влияние мероприятий из `static/events.json`
- `tools/add_event.py` — добавление события вручную
- `notifications.py` — уведомления о спросе и погоде с учётом настроек профиля
- `tools/build_poi_density.py` — сборка снимка плотности заведений из OpenStreetMap
- `static/district-poi.json` — снимок плотности заведений по районам (ODbL 1.0)
- `heatmap.py` — генерация карты спроса
- `traffic_analyzer.py` — анализ пробок
- `weather.py` — получение погоды (вспомогательный)

## Важно

- **Никогда** не коммить `.env` и токен бота.
- База данных — SQLite. На хостинге её обязательно надо держать в постоянной
  папке, иначе накопленные коэффициенты стираются при каждом обновлении кода.
- При запуске SQLite автоматически мигрирует старые профили и смены, сохраняя
  существующие данные.
- Прогноз спроса учитывает сообщения о коэффициентах, историю похожего дня и
  часа, **погоду** (Open-Meteo), **плотность заведений** по районам из
  OpenStreetMap, **сообщения водителей** о пробках, ДТП и спросе, а также
  текущие дорожные инциденты TomTom, если задан API-ключ. TomTom слегка снижает
  оценку доступности района рядом с инцидентами; это не наблюдение спроса. Он пока не
  использует число заказов, число машин-конкурентов, мероприятия и расстояние
  от точки. Оценка для такси основана на коэффициентах
  за последние два часа и в похожий день/час; оценка для курьеров — на личных
  сменах с районом и часами работы за последние 90 дней; при наличии данных
  учитываются транспорт и похожее время начала. Балл 0–100 — сравнительный ориентир, а не гарантированный
  объём заказов.
- При сохранении смены можно указать фактическое время начала. Тип транспорта
  берётся из профиля направления; прогноз сравнивает смены с таким же
  транспортом и похожим временем старта, а при нехватке выборки явно сообщает,
  что использует более широкую историю.
- API ограничивает частоту запросов для каждого пользователя и маршрута:
  до 120 чтений или 20 записей в минуту. Публичная конфигурация карты не
  лимитируется.
- Сообщения водителей влияют на балл ограниченно: вес растёт с числом разных
  авторов, затухает с возрастом (половина веса за 90 минут) и не может сдвинуть
  район больше чем на 12 %.
- Если смена не попала в прогноз, приложение объясняет причину: не указан район,
  не указаны часы или смена записана в другом направлении.
- В приложении есть блок «Как считается прогноз»: он показывает, какие факторы
  участвуют прямо сейчас, и напоминает, что балл — сравнение районов, а не число
  заказов.
- Если у курьера ещё нет смен, показывается стартовая оценка по плотности кафе,
  магазинов и вузов (OpenStreetMap): это решает холодный старт, но не заменяет
  персональную историю.
- Погода берётся из Open-Meteo: текущие условия влияют на балл, а до трёх
  ближайших почасовых интервалов показываются отдельно в шапке. Если источник
  недоступен, оценка считается без погоды, и это прямо указано в примечании.
- Прогнозы оцениваются только по доступным наблюдениям: коэффициентам такси и
  сохранённым курьерским сменам. Ошибка этих показателей не является измерением
  точности числа заказов или заработка, который пользователь мог бы получить.
- Уведомления о спросе и погоде отправляются (ТЗ, п. 16): цикл раз в 15 минут
  проверяет настройки профиля, «тихие часы» и выбранную частоту
  (сразу / раз в час / раз в день), а факт отправки пишется в таблицу
  `notifications`.
- Уведомления о дорожной обстановке пока основаны на сообщениях водителей и
  курьеров. TomTom используется только как фактор прогноза; отдельные
  уведомления о внешних пробках не подключены. Автоматический источник городских
  событий пока не подключён, уведомления о мероприятиях отключены в настройках.
- Аэропорты и мероприятия учитываются, только если подключены источники.
  Прилёты берутся по шаблону `FLIGHTS_API_URL` (пусто по умолчанию — тогда слой
  молчит). Мероприятия задаются в `static/events.json`; автоматический сбор
  афиш не настроен, а файл сейчас пуст.
- Сообщения сообщества — пользовательские наблюдения, а не подтверждённая
  статистика заказов. Они скрываются из общей ленты по TTL и могут быть
  модерированы администраторами из `ADMIN_IDS`.
- Удаление данных блокируется до окончания оплаченного периода подписки ЮKassa.
  Перед удалением отключи автопродление в профиле.

## Деплой на Bothost (99 ₽/мес, бот работает круглосуточно)

1. Зарегистрируйся на [bothost.ru](https://bothost.ru/register) и подключи этот
   репозиторий GitHub (или загрузи архивом).
2. Главный файл (entrypoint) — `bot.py`. Зависимости платформа поставит сама
   из `requirements.txt`.
3. В разделе «Переменные окружения» проверь `BOT_TOKEN` — это токен от @BotFather.
4. Добавь `YANDEX_MAPS_API_KEY` с ключом JavaScript API Яндекс.Карт. В кабинете
   Яндекса ограничь ключ доменом Mini App, иначе его смогут использовать на
   сторонних сайтах. Для внешних дорожных инцидентов создай API-ключ TomTom в
   [кабинете разработчика](https://developer.tomtom.com/) и добавь его как
   `TOMTOM_TRAFFIC_API_KEY`. Ключ передаётся только серверу и хранится в заголовке
   запроса, не в Mini App. Интервал кэша — 20 минут (около 2 160 запросов в месяц
   при одном постоянно работающем процессе), что укладывается в бесплатную квоту
   2 500 запросов/месяц для Traffic Incidents API. Необязательно:
   `FLIGHTS_API_URL` — шаблон источника прилётов, поддерживающий `{iata}`.
   Для оплаты добавь `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` из кабинета ЮKassa.
5. Добавь переменную `DB_PATH=/app/data/taxi_data.db`. Папка `/app/data` — это
   постоянное хранилище: база переживёт обновления бота. Бот найдёт её и без
   переменной, но с ней надёжнее.
6. Возьми тариф **Active** (99 ₽/мес). На бесплатном тарифе контейнер «засыпает»,
   и бот перестаёт видеть новые сообщения.
7. Нажми «Запустить» — логи видны прямо в браузере.
8. Включи для приложения публичный HTTPS-доступ к веб-порту (`PORT`) и задай
   полученный адрес в `WEBAPP_URL`. После перезапуска появится кнопка «Открыть
   Mini App». Команда `/app` также отправляет кнопку открытия.
9. В кабинете ЮKassa настрой webhook на
   `<WEBAPP_URL>/api/yookassa/webhook` для событий `payment.succeeded` и
   `payment.canceled`. Для реального магазина заранее согласуй автоплатежи с
   поддержкой ЮKassa и проверь настройку чеков.

### Сколько нужно ресурсов

Бот занимает около 170 МБ памяти и до 185 МБ в момент построения карты спроса.
1 ГБ на тарифе Active хватает с большим запасом.

## Проверка перед запуском

Одна команда проверяет конфигурацию, базу, статику, данные по районам, прогноз,
уведомления и админку:

```bash
python tools/preflight.py
```

Код возврата `0` — всё готово, `1` — есть критичные проблемы (`FAIL`).
Предупреждения (`WARN`) запуск не блокируют, но их стоит прочитать: например,
без `YANDEX_MAPS_API_KEY` карта коэффициентов не загрузится.
